  ### 2. Réponses à vos Questions Stratégiques : Lexers, Parsers & Spécifications                                                              
                                                                                                                                               
  #### A. ANTLR4 vs Alternatives Modernes : Que Choisir ?                                                                                      
                                                                                                                                               
  • ANTLR4 :                                                                                                                                   
      • Forces : Écosystème éprouvé, grammaire formelle déclarative unique .g4, gestion automatique des conflits et prédiction adaptative      
      (ALL(*)).                                                                                                                                
      • Limites : Génère du code souvent verbeux et fortement couplé à un runtime objet lourd.                                                 
  • ANTLR4 gère-t-il Rust ?                                                                                                                    
      • Non officiellement dans le dépôt principal d'ANTLR4. Il existe un runtime communautaire (antlr4rust), mais il impose un style orienté  
      objet Java qui s'adapte mal à l'ownership et aux lifetimes de Rust (surcoût de Rc<RefCell<...>>).                                        
      • Le standard en Rust pour l'industrie :                                                                                                 
          1. Lexer : logos https://github.com/maciejhirsz/logos (génère un automate déterministe ultra-rapide à la compilation via macros, zéro
          allocation).                                                                                                                         
          2. Parser : Descente récursive manuelle avec algorithme de Pratt pour les expressions (méthode de rustc, Roslyn, Clang) ou           
          combinateurs comme chumsky / pest.                                                                                                   
  
  • Le standard en C++ :
      • Descente récursive + Pratt avec allocation d'AST dans une Arena de mémoire contiguë (aucun std::shared_ptr, destruction O(1) en bloc,  
      cache L1/L2 saturé).
  

  #### B. Et si l'équipe n'a qu'un fichier de spécifications informel (.md, .txt) ?
  
  C'est précisément l'une des forces du modèle Agent Harness :
  
  1. Étape d'Ingestion : L'agent explore la spécification non formelle fournie dans .harness/knowledge/domain/.
  2. Formalisation EBNF & Tokens : L'agent dérive automatiquement la grammaire formelle (règles de précédence, tokens, associativité).         
  3. Batterie de Golden Tests : Avant d'écrire le moindre parser, l'agent génère des extraits de code source valides et invalides avec leur AST
  cible attendu en JSON.
  4. Implémentation Conforme : Le lexer et le parser sont alors développés sous la contrainte stricte des golden tests et validés par le juge.

## 2. Corpus transverse (`.harness/knowledge/domains/`)

- **`fullstack/README.md`** — index + règles de chargement (routage lead/playbook)
- **`fullstack/app-performance.md`** — la boucle mesurer→hypothèse→corriger→garder, métriques (Web Vitals, p99, event loop delay), gains par ordre d'impact backend/frontend, frontière Web↔Serveur, 6 anti-patterns interdits, checklist
- **`fullstack/platform-production.md`** — statelessness, lifecycle (readiness ≠ liveness, graceful shutdown), boîte à outils fiabilité (timeout/retry/breaker/bulkhead/shedding/files), observabilité (RED/USE, SLO, OTel), déploiement (canary, expand/contract), conteneurs durcis, sécurité, capacité — le tout **ancré à vos artefacts réels** (verify.sh en CI, `jobId`/`resultChecksum` déjà dans vos schemas Zod, `bridge.isHealthy()`)
- **`scientific/README.md`** + **`scientific-in-production.md`** — la règle d'or « un résultat presque correct est une réponse fausse avec de bonnes manières » ; reproductibilité (seed, provenance), sécurité numérique aux frontières (NaN/Inf rejetés entrée ET sortie, tolérances adossées à une référence), orchestration jobs (file → worker pool → binaire natif, idempotence, déduplication par empreinte, quotas mémoire), monitoring du drift scientifique

  ### 2. Corpus Transverse de Production ()                                                                                                    
                                                                                                                                               
  Deux corpus transverses majeurs ont été formalisés et intégrés :                                                                             
                                                                                                                                               
  #### A. Plateforme & Performance Fullstack (domain/fullstack/)                                                                               
                                                                                                                                               
  • app-performance.md :                                                                                                                       
      • Boucle empirique à 5 étapes : Mesurer (baseline) → Hypothèse → Corriger → Mesurer à nouveau → Garder/Rejeter.                          
      • KPIs stricts : Web Vitals (LCP ≤ 2.5s, INP ≤ 200ms), latence API p99 ≤ 50ms, Event Loop Delay ≤ 10ms.                                  
      • Frontière Web/Serveur : Compression Brotli, gestion ETag conditionnelle HTTP 304, flux binaire zéro-copie (Float64Array).              
      • 6 anti-patterns interdits : Blocage de l'Event Loop, cache sans TTL/LRU, cascades de requêtes (waterfalls), polling naïf, bundle       
      monolithique.                                                                                                                            
  • platform-production.md :                                                                                                                   
      • Architecture 100% Stateless : Aucun état de session en mémoire vive processus.                                                         
      • Cycle de vie Kube/Docker : Séparation stricte /health/liveness vs /health/readiness, arrêt gracieux sur SIGTERM.                       
      • Boîte à outils de résilience : Timeouts obligatoires, retry exponentiel avec jitter, circuit breaker, cloisonnement (bulkhead),        
      délestage de charge (load shedding).                                                                                                     
      • Observabilité : Méthodes RED (services) et USE (ressources), logs structurés JSON avec identifiant de corrélation (X-Request-Id).      
                                                                                                                                               
                                                                                                                                               
  #### B. Rigueur & Calcul Scientifique en Production (domain/scientific/)                                                                     
                                                                                                                                               
  • scientific-in-production.md :                                                                                                              
      • Règle d'or : « Un résultat presque correct est une réponse fausse avec de bonnes manières. »                                           
      • Reproductibilité absolue : Graines PRNG isolées, traçabilité de provenance (empreinte SHA-256 des entrées, drapeaux de compilation,    
      resultChecksum Zod).                                                                                                                     
      • Sécurité numérique étanche : Bannissement total des NaN et ±Inf aux frontières d'entrées et de sorties d'API.                          
      • Orchestration asynchrone des jobs lourds : File de tâches découplée du thread HTTP, idempotence des requêtes, quotas mémoire stricts.  
      • Monitoring du Drift : Surveillance du nombre de conditionnement matriciel κ(A) et de la norme des résidus ‖Ax - b‖.
